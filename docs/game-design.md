## 1. 概述

### 1.1 一句话介绍

**永夜吞掉了天上星宿落到人间的光，连起九州城池的“星线”一段段熄灭。你是望星城的持线人，带着五方的伙伴把星线重新连起来：上车掏出手机，摆好阵、连好星络、推演一下胜率，看 Q 版小人自动打完一关，下车正好收工。**

### 1.2 设计目标

| 目标 | 具体要求 |
|---|---|
| 不打卡 | 没有每日任务和体力；需要联网登录，养成数据存在服务器上（决策 49），但玩法仍以单人为主，排行榜等在线功能不玩也没有损失 |
| 碎片时间玩得完 | 打开 30 秒内进战斗；一关 2 分钟内；远征 8~10 分钟且可以中途退出；单手竖屏能操作（决策 69） |
| 策略在布阵 | 选兵、站位、星络、克制；战斗自动进行，只保留 1~2 个指挥官技能 |
| 有辨识度 | 星络（连星成宿）和战前推演是同类游戏没有的核心机制；星宿国潮的画面和题材 |
| 长期吸引 | 每局不同的远征、难度阶梯、解锁与图鉴、炼金工坊研究、无尽的星辉高塔 |

### 1.3 参考游戏

| 游戏 | 借鉴点 |
|---|---|
| 背包乱斗 / Mechabellum | 布阵自动战斗、异步对战其他玩家的阵容 |
| 杀戮尖塔 | 随机路线、难度阶梯 |
| FTL：超越光速 | 远征、资源和补给管理 |
| 云顶之弈 / 自走棋 | 合成升星、阵容搭配 |
| 微信小游戏的放置和塔防类 | 竖屏单手、一关几分钟、离线收益、激励视频只给便利 |

### 1.4 平台与商业模式

- **平台**（决策 66）：微信小游戏和安卓 App 同步做，同一个团结工程出两个包。安卓 App 没有版号只能在 TapTap 发不收费的测试版（国内正式商店和 iOS 国区都要版号），同样靠广告；抖音小游戏第二步；海外 iOS / 安卓、Steam 搁置（相关代码保留，以后再接）。
- **引擎**：团结引擎 1.10.4（基于 Unity 2022.3），URP 14，用团结的小游戏转换流程发布。小游戏跑在 WebAssembly 上，泛光、实时阴影、骨骼动画数量都按手机降一档。
- **资源**：首包只放启动必需的内容；角色模型、音乐、字体、语言表放 UOS CDN 按需下载。
- **账号**：小游戏用微信登录，换成服务端账号，一个账号一个存档；App 端的登录方式和跨端同一存档的绑定由服务端设计决定（[server-design.md](server-design.md)）。

**商业模式**（决策 67）：国内没有版号，游戏里不能收费，只做广告变现。

| 广告位 | 给什么 | 原则 |
|---|---|---|
| 激励视频：奖励翻倍 | 关卡、扫荡、离线收益翻倍 | 玩家自己选看不看，不看也不卡进度 |
| 激励视频：再来一次 | 失败后直接重打，保留推演结果 | 本来就没有体力，只是省时间 |
| 激励视频：多一次刷新 | 远征三选一、商店多刷一次 | 不直接给碎片 |
| 插屏 / Banner | 尽量不用，最多只在结算页 | 打断节奏最伤留存 |

- 不卖碎片、经验、金币，不做付费抽卡和体力；碎片需求和掉落按“只花时间”设计，不为广告拉长。
- 以后要做内购，只能找有资质的发行商代理拿版号，或注册公司自己申请；现在不考虑。
- 上线前要办：小游戏备案、游戏自审自查材料（可能需要软著）、内容审核。个人主体能开的类目和流量主门槛以微信公众平台当时的规定为准。
- 所有平台都必须联网登录才能玩，不提供离线模式（决策 49）。
- **发行策略**：首发第一幕（三章）和约 15 名角色，尽早上线看留存数据，靠更新追加章节和角色。
- 原来的 Steam 买断 + DLC、海外一次性内购方案见决策 58，搁置。

## 2. 世界观与剧情

> 完整的故事背景、五个阵营、三幕九章和角色关系见 [story.md](story.md)，以它为准；本节是概要。
>
> **v4.0 改题材（决策 68）**：2.1、2.2 已按星宿国潮改写；2.3 起的人名、地名和 Boss 还是 v3.0 名称，等 story.md 重写时一起改。主线结构（五根线、永夜、断线日、诺娃的倒计时和结局）不变。

### 2.1 背景

很久以前，天上的二十八星宿落下一场星雨，碎星化成了蕴含灵力的**星石**。织女带着人间的术士和山林里的灵族，把星石一颗颗立在九州城池之间，让灵力沿着星石流转，连成一张和天上星宿一样的网。夜里星石连成的光带像落在地上的银河，所以人们叫它**“星线”**。城池的结界、灯火、田地和传信，全靠星线供给灵力。

星线其实是一道封印：它把吞食灵力的**永夜**压在大陆尽头。某一年，朱雀司天监的前任监正打开了星线源头的**初源星石**，想独自撑住衰竭的封印，反被永夜吞掉。永夜一夜之间吸干了成千上万颗星石，星线断成碎片，这一天叫**断线日**。被永夜的墨色侵蚀的人成了**墨蚀者**：他们不是天生的妖魔，是陷落城池的百姓和守军，记忆被墨色封住，只剩下饥饿。

星线最末端的边城**望星城**靠一座观星台撑了下来。观星台的星石里住着一缕星魂**诺娃**，她是织女留下的最后一位织网者，能预见战局，却记不起自己是谁。玩家是观星台选中的**持线人**，任务是：**沿着星线一段段打回去，重新点亮星石，把失联的城池重新连起来。**

**最终目的**：重织星线。当年的网只用了两根线，所以迟早会断；这一次要集齐五方的五根线（玄武的守护、白虎的自由、朱雀的知识、青丘的信任、墨蚀者的救赎），织一张把所有人连起来的网。收集五方的伙伴就是在推进主线。

**核心主题**：连星成宿。战斗里你在布阵连线，剧情里你在把九州重新连起来。宣传语：“星线不断，人间长明。”

### 2.2 势力

五个阵营对应五方，每方出一根线（决策 68，名称为草案）：

| 阵营 | 方位 | 身份 | 风格 | 那根线 |
|---|---|---|---|---|
| **玄武营** | 北 | 望星城的守军：重甲、盾卫、弩手 | 耐打，守住星石 | 守护 |
| **白虎游骑** | 西 | 边塞的游侠和弓骑 | 快，绕后 | 自由 |
| **朱雀司天监** | 南 | 观星的术士，掌管星线的学问 | 远程术法，依赖星络 | 知识 |
| **青丘灵族** | 东 | 山林里的狐族和花木精，当年和织女一起织网 | 隐身、闪现突袭；第三幕从敌人变为盟友 | 信任 |
| **墨蚀者** | 中 | 被永夜侵蚀的人，可以被唤醒 | 数量多、墨色剪影、发紫光；也有自己的“墨碑”星络 | 救赎 |

造型规则：Q 版大头；墨蚀者用墨色剪影和发光的眼睛表现，不用骷髅、尸体、腐肉和血腥。

### 2.3 主要角色

| 角色 | 身份 | 作用 |
|---|---|---|
| 指挥官（玩家） | 晨星远征军指挥官，唯一听得见诺娃的人 | 主角；结局里把五根线打成结。不配语音、不定性别 |
| 诺娃 | 栖身在源晶塔水晶里的星灵，远征军的参谋 | 战前推演的“参谋”（用水晶预见战局）；身世是剧情主线之谜（最后一位织网者），从第 5 章起光越来越暗，是故事的倒计时；结局里散进整张星线 |
| 雷恩爵士 | 老骑士，灯塔城守备司令 | 第一、二幕的导师，第二幕为守住水晶牺牲 |
| 林大师 | 首席炼金师 | 负责炼金工坊和解析研究 |
| 卡西 | 王牌狮鹫骑士 | 擅长切断敌方魔网，战斗中常有喊话；也是可上阵的角色（8.3） |
| 维拉 | 影歌精灵使者 | 第三幕登场，揭示星线的真相 |
| 莫德雷德 | 银月法师塔前任塔主，巫妖王 | 最终 Boss。想独自撑住衰竭的封印，反被永夜吞掉（第 6 章揭开）；通关后作为传说角色加入 |

### 2.4 三幕剧情（一局远征的三幕）

| 幕 | 区域 | 剧情 | 幕末 Boss |
|---|---|---|---|
| 第一幕 | **边境行省** | 从灯塔城出发，夺回第一批水晶，连通三座边境城邦 | **骸骨要塞**：亡灵用断线日倒下的守军尸骨和碎水晶垒成的要塞 |
| 第二幕 | **王国腹地** | 连通被围困的城邦；发现亡灵在吞食水晶里的法力并不断变强；雷恩爵士为守住水晶牺牲 | **噬魔巨龙**：吞下了一整座水晶枢纽的骨龙 |
| 第三幕 | **永夜之地** | 与影歌精灵从交战到结盟，得知星线最初是为了封印亡灵而织成的；诺娃是织网者留在水晶里的一缕意识 | **巫妖王**：盘踞在星线起点“初源水晶” |

- 每次远征都完整打一遍三幕。
- **剧情按进度解锁**：首次到达某一幕、首次击败某个 Boss、累计完成远征次数，都会解锁新的剧情片段。通关后解锁“难度阶梯”和后续剧情。

### 2.5 剧情呈现

| 方式 | 用在哪里 |
|---|---|
| 立绘对话 | 每幕开始、Boss 战前后、远征结算 |
| 战斗喊话 | 战斗中屏幕角落弹出角色头像和短句，不暂停 |
| 角色语气 | 角色之间可以互相调侃、拌嘴，喊话和对话带出各自的性格（参考《我叫MT》系列：玩家记住角色，靠的是性格鲜明的台词，而不是数值）；主线的严肃段落保持正经 |
| 事件节点 | 远征中的剧情选择题 |
| 档案 | 敌人、角色、水晶、城邦的背景故事，在图鉴中解锁 |
| 章末钩子 | 主线每章最后一关的结束对话以一个悬念收尾（[story.md](story.md) 第 3 节） |
| 通关总结 | 主线通关后依次播放：打结、各阵营尾声（★5 角色有个人结局）、旅程回顾「星线编年」、诺娃的信和最后一张布阵图（[story.md](story.md) 第 4 节） |

所有剧情都可以跳过，并能在档案馆重看。

**旅程数据**：通关总结要用到玩家自己的数据，从第一关起记在存档里（随账号存档保存在服务端）：每关胜负和失败次数、每场上阵阵容、战前推演次数、首次通关时间。

## 3. 游戏结构

| 模式 | 节奏 | 作用 |
|---|---|---|
| **主线战役**（[story.md](story.md)、4.8 节） | 一关 1~2 分钟，三幕九章 | 主体验：剧情、招募角色；打过的关卡可以重复挑战，刷经验和碎片 |
| **远征**（第 4 节） | 一局 8~10 分钟，可以中途退出 | 挑战模式：带自己培养的角色闯三幕 Roguelite 路线，产出碎片和符文 |
| **星辉高塔**（第 11 节） | 一层 1~2 分钟 | 常驻休闲：碎片时间玩几层，长期目标是走得更远 |
| **炼金工坊**（第 10 节） | 局外 | 用缴获的遗骸解析敌方的力量 |
| 在线玩法（第 12 节，可选） | — | 异步挑战其他玩家阵容、排行榜 |

**碎片时间**（决策 69）：坐一站地铁打一两关主线或几层星辉高塔；上下班各打开一次领离线收益；有十分钟就开一局远征，没打完下次接着打。

## 4. 远征（Roguelite 挑战模式）

> **v4.0（决策 69）**：一局缩到三幕各 2 个节点 + Boss，约 8~10 分钟；进度存在服务端，可以随时退出、下次接着打。下面 4.1~4.4 的节点数和时长按这个改，其余规则不变。
>
> 改成长期养成后，远征保留为挑战模式（决策 41）：出发前从自己的角色里选阵容，带着等级和星级出发。下面 4.1~4.7 是原来的局内规则，局内合成升星等细节要按新方向改，见 4.8 末尾。

流程图见 [prototype/RunFlow.png](prototype/RunFlow.png)。

### 4.1 一局的流程

```
开局：选指挥官，带 3 名初始角色和 1 个指挥官技能
  → 第一幕 边境行省（2 个节点）→ Boss：骸骨要塞
  → 第二幕 王国腹地（2 个节点）→ Boss：噬魔巨龙
  → 第三幕 永夜之地（2 个节点）→ Boss：巫妖王
  （v4.0 每幕 2 个节点；Boss 名称待按新题材改，见附录）
  → 结算
```

### 4.2 地图节点

| 节点 | 内容 |
|---|---|
| 普通战斗 | 常规敌人，胜利后战利品三选一 |
| 精英战 | 更强的敌人，掉落稀有角色或符文，遗骸掉率更高 |
| 玩家阵容 | 其他玩家在同一幕的真实阵容（异步对战，没有合适的玩家阵容时换成 AI 阵容） |
| 事件 | 剧情选择题：救援难民车队、调查水晶遗迹、和流浪商人交易等 |
| 商店 | 用金币购买角色、符文、指挥官技能 |
| 补给站 | 二选一：恢复 1 点远征军耐久，或领取 1 个法力水晶（P3 加入口粮） |

每次在地图上有 2~3 条路线可选。

### 4.3 战斗循环

```
选节点 → 布阵（可看到敌方阵容，可一键上阵）→ 战前推演（可选）→ 自动战斗 20~45 秒
  → 胜利：战利品三选一（角色 / 符文 / 指挥官技能）→ 整备 → 下一个节点
  → 失败：远征军耐久 −1，没有奖励，跳过这个节点回到地图（Boss 战失败 −2，可以重打）
```

### 4.4 局内资源

| 资源 | 规则 |
|---|---|
| 远征军耐久 | 共 5 点；战斗失败 −1，Boss 战失败 −2；归零则本局结束 |
| 金币 | 战斗获得，商店消费（P3） |
| 口粮 | 每跳一个节点消耗；不足时角色法力上限降低，需要去补给站（P3） |
| 指挥点上限 | 第一幕从 12 开始，每过一个战斗节点 +2（输赢都算，避免一场失败滚雪球），最高 24；之后每幕提高起点 |
| 情报点 | 每场战斗 3 点，用于战前推演 |

### 4.5 局内成长

- **合成升星**：3 名同名同星角色自动合成 1 名高一星的（最高 3 星）。★2 耐久（生命、护盾、护盾恢复）×1.6、伤害 ×1.5；★3 耐久 ×2.5、伤害 ×2.2。合成后的角色接替原来的上阵位置。
- **角色不会永久损失**：战斗中倒下的角色战后全部恢复，失败的代价是远征军耐久。
- **符文**：装到角色的符文槽上（见 8.5）。
- **指挥官技能**：最多带 3 个。

### 4.6 局外成长（轻量）

- 新角色、新符文、新指挥官、新指挥官技能**加入奖池**（不是直接变强）。
- 图鉴、成就、外观。
- **难度阶梯**：通关后解锁“威胁等级 1~20”，每级给敌人加一条规则。
- 炼金工坊研究成果（第 10 节）。

### 4.7 第一幕的实现（P2）

已在代码中实现，数值由自动玩家批量模拟校准（`tests/Starline.Battle.Tests`）。

| 项目 | 内容 |
|---|---|
| 开局远征军 | 源晶塔、2 个法力水晶、重甲骑士 / 游侠 / 奥术法师各 1 名（共 10 指挥点） |
| 地图 | 6 层：战斗 ×2 → 战斗、战斗、补给 → 战斗、精英、补给 → 战斗 ×2、精英 → 补给、战斗 → Boss；每层顺序随机，节点连向下一层相邻的 1~2 个节点 |

| 战利品 | 三选一；一半选项是已拥有的角色（方便合成）；第三个选项有 1/4 概率换成法力水晶（最多 6 个）；精英战第一个选项是 ★2 |

### 4.8 角色养成：刷关升级、碎片升星（新方向，草案）

开发者要求：用一整个故事把各阵营的角色串起来，玩家通过反复挑战关卡（刷图）给角色升级、收集角色碎片给角色升星。这一节是方案草案，和上面“一局远征”的关系见末尾。

**获得角色**

- 剧情加入：每章固定加入 1~3 名角色，其余角色从对应章节起掉落碎片（见 [story.md](story.md) 第 3 节“角色加入”表）。
- 碎片召唤：集齐 10 个碎片招募一名角色，敌对阵营的角色（亡灵、精灵）主要靠这条路。

**等级**

- 角色等级 1~60，经验来自关卡。打过的关卡可以重复挑战。
- 星级决定等级上限：★1 上限 20，每升一星 +10。

**星级**

- ★1~★5。升星消耗本角色的碎片：★2 需 20 个，★3 需 40 个，★4 需 80 个，★5 需 120 个。
- 星级倍率（耐久 / 伤害）：★2 1.6 / 1.5，★3 2.5 / 2.2，★4 3.5 / 2.9，★5 4.6 / 3.6（★4、★5 为草案，决策 56）。模拟里一名高一星大约顶 1.8、1.7、1.5、1.4 名低一星，★5 约等于 5 名 ★1（见 8.6）。
- 每升一星：属性提高，并解锁一个符文槽或强化一个专属技能，再解锁一段个人小故事。
- 外观：每升一星换一档更华丽的服装和装备（银饰 → 金边刺绣披风 → 宝石和传说配色，见 [art-direction.md](art-direction.md)“升星外观”），底座也跟着加银边、金边、镶宝石（底座只在展示、升星、图鉴界面出现，战斗里不放）；体型每星略微放大。

**碎片从哪来**

| 来源 | 说明 |
|---|---|
| 主线关卡 | 每关标明掉落哪 1~2 名角色的碎片；三星通关后可以“扫荡”，不用再手动打 |
| 精英关卡 | 每章 3 个，碎片掉得多，对应该章加入的角色 |
| 星辉高塔 | 每 10 层奖励一次自选碎片 |
| 炼金工坊 | 解析遗骸得到亡灵角色的碎片 |
| 商店 | 用关卡掉落的金币兑换指定角色的碎片 |

**资源关卡**

除了主线关卡，常驻开放四条资源线，玩家缺什么刷什么：

| 资源线 | 产出 |
|---|---|
| 经验 | 角色经验 |
| 金币 | 金币（商店兑换碎片、升级符文） |
| 碎片 | 每天轮换 3 名角色的碎片（轮换只是换产出，不限次数） |
| 符文 | 符文和符文强化材料 |

- 每条线分若干难度档，随主线进度解锁；三星后可扫荡。
- 没有次数限制，也不消耗体力。

**重置返还**

- 任何角色都可以随时**无损重置**：等级回到 1 级，消耗的经验和金币全部返还，卸下的符文回到背包。星级和碎片不返还（升星是永久收集进度）。
- 目的：玩家敢换阵容，45 名角色都有机会上场，不会因为“资源已经砸在某个角色身上”而只用固定几名。
- 重置在服务器上结算，免费、无冷却。

**离线收益**

- 下线期间，远征军驻守在已通关的最远一章，按章节进度累积**经验和金币**，上线时一次领取。
- 最多累积 12 小时；不产出碎片和符文，只是“回来时有东西领”，不做成“不上线就亏”。
- 由服务器按下线时间计算（需要联网登录，见决策 49）。

**广告**（决策 67）：关卡、扫荡和离线收益可以看激励视频翻倍，失败可以看激励视频直接再来一次；都是可选的便利，不看也不影响进度。

**不做的东西**：没有体力、没有每日次数、没有付费抽卡，任何平台都不卖碎片和经验（决策 58、67）。刷图只花时间；扫荡和自选碎片用来控制重复劳动。商店兑换碎片只用关卡掉落的金币，不设付费货币。

**和远征的关系**：主线改为章节关卡，远征保留为挑战模式（决策 41）。

- 出发前从自己的角色里选 3 名首发，带着等级和星级。
- 局内战利品改为：临时加入的角色（只在本局有效）、符文、指挥官技能。局内 3 名同名合成的规则取消。
- 远征结算按走到第几幕发碎片和金币，Boss 掉落对应阵营角色的碎片。
- 现有的远征代码、关卡配置和平衡模拟继续用，改动集中在开局阵容和战利品。

## 5. 布阵与战斗

原型图见 [prototype/Formation2.png](prototype/Formation2.png) 和 [prototype/Battle2.png](prototype/Battle2.png)。

### 5.1 布阵棋盘

- **竖向战场**：我方在下、敌方在上，双方前排隔着中间的接触线相对（决策 52，为了适配微信等竖屏平台）。
- **v4.0（决策 69）**：每一方改为**前排宽 5 格、纵深 3~4 格**（竖屏原型试玩后定），一格要够手指点准；上阵人数和指挥点上限跟着降。小型和中型角色占 1 格，**大型单位占 2 × 2 格**。（内核现在仍是 8 × 6，改尺寸要重跑平衡模拟。）
- 星络节点（原法力水晶）改放在**格子**上（见第 6 节）。
- **一键上阵**按推荐站位摆好；**沿用上次阵容**直接开战。
- 上阵数量受**指挥点上限**限制。
- 布阵可以保存为方案。

| 位置 | 适合 | 原因 |
|---|---|---|
| 前排 | 重甲骑士、游侠 | 先接敌，承受伤害 |
| 后排 | 奥术法师、源晶塔 | 射程远，需要保护 |
| 两翼（前排的左右两端） | 狮鹫骑士、游侠 | 速度快，绕后攻击 |

**能否看到敌方阵容**：远征的普通节点和星辉高塔可以看到；少数“迷雾”节点看不到；实时对战看不到（见第 12 节）。

### 5.2 自动战斗

- 角色按固有的**索敌偏好**自动选目标：狮鹫骑士优先攻击魔网节点和远程单位，弩手优先攻击狮鹫，奥术法师优先攻击重装单位，其余攻击最近的目标。
- 移动到射程内后攻击；狮鹫在大型单位之间穿梭，不和它们碰撞。
- 默认 2 倍速，可以切 1x / 4x，或者跳过。
- **视角**（决策 69 取代决策 53）：只留默认斜看和俯视两个预设，点一下切换；单手玩不做拖动旋转。视角只影响观看，不影响战斗结果。
- 时间上限 45 秒（v3.0 是 90 秒，改了要重跑平衡模拟），到时比较双方剩余作战单位的耐久。

### 5.3 指挥官技能

每场战斗带 1~2 个（v4.0，决策 69；按钮放在屏幕下方，单手好按），消耗**法术点数**（开局 2 点，每秒 +1，上限 10）：

| 技能 | 消耗 | 冷却 | 效果 |
|---|---|---|---|
| 陨星术 | 4 | 10 秒 | 选择落点，1 秒后对范围内敌人造成大量伤害 |
| 守护结界 | 3 | 15 秒 | 全体恢复一半护盾 |
| （更多技能在远征中获得） | | | 传送增援、驱散波、水晶过载等 |

### 5.4 威慑

- 开战时比较双方上阵战力；一方超过对方 1.5 倍时，对方进入“被威慑”：射速 −10%。
- 弱势方击败对方大型单位时触发“士气爆发”，解除被威慑并短时提高伤害。
- 远征中遇到明显弱于自己的敌人时，可以直接威慑对方投降，跳过战斗并拿到一半奖励。

### 5.5 战斗场景与地形（决策 55）

每场战斗发生在剧情里的某个地方，场景分两层，都只做加成，不改角色的定位和攻击方式：

| 层 | 范围 | 作用 |
|---|---|---|
| **战场环境** | 整场战斗，双方都吃 | 按阵营、职业给 2~3 条 buff / debuff，部分环境改魔网规则 |
| **地块** | 棋盘上的部分格子（每方半场约 4~10 格） | 站在上面的角色加减移速、射程、受到的伤害；有的格子不能布阵 |

**每章一种主场景**（一章 10 关共用同一种环境，地块布局每关不同）。数值为草案，标 ✓ 的已在内核实现并跑过平衡模拟：

| 章 | 场景 | 环境效果 | 代表地块 |
|---|---|---|---|
| 1 灯塔城 | ✓ 城郊草原 | 无（教学章） | 高地、浅水 |
| 2 游侠的森林 | ✓ 古木森林 | 边境游侠会、影歌精灵移速 +15%；远程射程 −1 格（树冠遮挡）；重装移速 −10% | 灌木、高地 |
| 3 骸骨要塞 | 骸骨荒原 | 亡灵每秒回复 1% 生命；支援的治疗效果 −25%；亡灵骨碑覆盖 +1 格 | 骨堆、断墙（高地） |
| 4 银月法师塔 | 奥术庭院 | 银月法师塔法力恢复 +30%；飞骑受到伤害 +15%；魔网连线距离 3 → 4 格 | 法力泉、高地 |

| 地块 | 效果 | 谁不受影响 | 能否布阵 |
|---|---|---|---|
| 高地（断墙、土坡、沙丘） | 远程和对空射程 +1 格；受到远程伤害 −15% | — | 能 |
| 灌木 | 受到远程伤害 −20% | — | 能 |
| 浅水 | 移速 −30%；水面导魔：角上交叉点的法力水晶连线距离 +1 格 | — | 能 |
| 深水 / 冰裂缝 / 虚空裂隙 | 穿过时移速 −60%；水面导魔同浅水 | — | **不能** |
| 流沙 | 移速 −40% | 边境游侠会 | 能 |
| 沼泽 | 移速 −30%；攻速 −10% | 影歌精灵 | 能 |
| 冰面 | 移速 +25%；不回复护盾 | — | 能 |

| 法力泉 / 水晶簇 | 角上交叉点的法力水晶覆盖 +1 格 | — | 能 |

**规则**

- 环境效果按阵营或职业生效，地块效果按角色中心所在的格子生效，不按单个角色写特例。
- 百分比效果单条 ±10%~20%，地块减速可到 −60%；射程和覆盖只加减整格。同一属性的地形修正合计夹在 50%~140%（移速下限 40%），射程最多 ±2 格且不短于 1 格。和职业克制、阵营克制、羁绊叠乘。
- 第一版不做阻挡和寻路：深水这类格子只是不能布阵、穿过时大幅减速。
- 布阵界面显示场景名和效果，棋盘上标出地块，受影响的角色头顶显示 ↑ / ↓；战前推演直接带地形计算。
- 平衡：自动玩家模拟对每种环境比较“有 / 无环境效果”，环境效果把同一场战斗的胜率改变超过 15 个百分点就削弱。地块对固定阵型的影响很大（同一场战斗在不同布局下胜率 0%~85%），这是有意的：玩家要按地块调整布阵，战前推演会把影响算出来。

**场景生成**

- 地块布局（影响胜负，在内核里生成，必须确定）：关卡配置写 `terrain`（环境 id），再写手绘的 `layout`（Boss 关、剧情关），或者只写 `layoutSeed`（普通关，缺省按关卡 id 算）。生成器用确定性随机数，同一关每次进来地形一样。约束：双方半场每种地块数量相等；地块连成片；源晶塔所在的后排中间保持空白；每方不能布阵的格子不超过 6 个，前排至少留 4 个空位，前四排留一块 2×2 空地。
- 场景美术（只管好看，在客户端生成）：每种环境一套地面材质和光照预设（写在 JSON 里）；地块用单独的网格（水面、抬高的高地、灌木）；棋盘外按环境自动摆放树、岩石、断柱、骨堆、水晶簇等道具；竖屏镜头的远景（敌方后方）放每章的地标（源晶塔、法师塔、湖心枢纽、初源水晶）。道具和角色模型一样用 Blender 脚本生成。
- 录像和校验：地形是战斗配置的一部分，录像带上环境 id 和地块布局（或种子），服务器用同一份内核重算。

**进度**：第一期（内核、四种环境、十种地块、测试）已完成；第二期做客户端表现（等竖屏构图合并后）；第三期补齐其余五种环境、天气变体、远征和高塔接入。

## 6. 魔网（核心玩法）

> **v4.0（决策 68、69）**：魔网改名“星络”，法力水晶改名“星石”，源晶塔改名“观星台”。手机上交叉点太小点不准，星石改为**放在格子上**（占一格，不能和角色同格），两颗星石在同一行或同一列、相距不超过 3 格时自动连线，覆盖范围按格子中心计算；切断、接入和未接入的规则不变。内核按这个改之前，下面 6.1 仍是现在实现的交叉点规则。

### 6.1 规则

- 角色占格子；**魔网在另一层：节点放在格子交叉点上，魔网连线沿格线走。**
- 每场战斗己方后方有一座固定的**源晶塔**（大型，占 2 × 2），它前沿中点的交叉点是**源口**。
- 布阵时可以在交叉点上放**法力水晶**，每个消耗 1 指挥点。
- 两个节点在同一条格线上、相距不超过 **3 格**时自动连成魔网连线。
- 每个节点**覆盖周围 2 格**（以交叉点为中心的 4 × 4 区域）。
- 角色只要有一格在覆盖范围内，并且这个范围的节点能沿魔网连线连回源口，就算**接入魔网**。

### 6.2 接入和未接入

| 状态 | 法力 | 护盾恢复 |
|---|---|---|
| 接入魔网 | 持续补充 | 正常 |
| 未接入 | 只有自身的法力，用完就停手 | 停止 |

- 狮鹫骑士有“短时离网”特性：离开覆盖范围后 10 秒内仍算有魔网，适合执行切断任务。

### 6.3 切断

- 战斗中**法力水晶可以被摧毁**；被毁后网络重新计算，下游的节点和角色全部断魔网。
- 亡灵也有自己的魔网（亡灵祭坛 + 骨碑），布阵时可以看到，并规划切断路线。

### 6.4 带来的策略

- 阵型紧凑容易覆盖，但怕范围攻击；阵型分散需要更多水晶。
- 派狮鹫骑士绕后切断敌方魔网，敌方远程单位用光法力就失去威胁。
- 在关键水晶附近放弩手，挡住来切线的怨灵。

已在战斗内核中实现并测试：默认阵型胜率约 27%；把未接入魔网的奥术法师挪进覆盖区约 77%；去掉全部法力水晶为 0%。

## 7. 战前推演（招牌功能）

- 布阵后点“战前推演”，消耗 1 点情报点，内核在后台用不同随机种子**模拟 100 场**，约 1 秒出结果。
- **v4.0（决策 69）**：小游戏跑在 WebAssembly 上，手机上 100 场可能要好几秒。改为点一下出胜率，场数降到 20~30 场（误差会变大），或者交给服务端算；在竖屏原型里实测后定。
- 结果：**胜率与误差范围、平均用时、平均损失、常见败因、参谋（诺娃）建议、本场推演记录**。
- 限制：
  - 情报点有限（每场 3 点）。
  - 推演不使用指挥官技能。
  - 敌方部分单位有**隐藏特性**，推演按默认值计算，因此有误差；炼金工坊研究可以消除（见第 10 节），商店可以买“侦察”。
  - 真实战斗使用推演中没用过的随机种子。
- 宣传语：“开战之前，你已推演了一百场战争。”

|---|---|---|
| 晨星骑士团 | 亡灵 | 圣光克制不死 |

- 敌方阵容也按同样的规则吃羁绊，所以“亡灵 6 人”的关卡会明显更难。

### 8.5 固有属性与符文

- 每名角色有**固有属性**（定位、尺寸、生命值、护盾、伤害、射程、速度、法力、专属技能、固有特性），决定它的玩法，任何符文都不能改变定位、射程档位和攻击方式。
- 每名角色有 **3 个符文槽**（槽 1 主动、槽 2 和槽 3 被动；槽 2、槽 3 分别在 2 星、3 星解锁），安装远征中获得的符文。
- **双向装配限制**：角色的槽位规定接受哪些符文类别（攻击 / 防御 / 机动 / 支援 / 咒术 / 特殊）；符文规定适用哪些角色（按定位、尺寸、攻击方式）。两边都满足才能装。
- 符文只做补充：一名角色的战力中，固有属性占 75% 以上，符文不超过 25%。

### 8.6 数值平衡表与对战模拟（决策 56）

所有影响胜负的数值（角色属性、阵营、职业克制、星级倍率、战场环境和地块）汇总在 [balance-sheet.md](balance-sheet.md)。这份表由测试程序从 JSON 配置表生成，并用内核跑约 6000 场纯逻辑对战（20 秒左右），改数值后重新生成：

```
dotnet run --project tests/Starline.Battle.Tests -- --balance      # 可在后面加种子数，默认 6
```

模拟只看角色固有属性，不含指挥官技能、羁绊和专属技能（都还没进内核）；影歌精灵还没有做出数值的角色，第一版只比较 10 名已有数值的角色。

**现在的结论**（2026-10，用当时的配置表）：

| 检查 | 结果 | 建议 |
|---|---|---|
| 职业克制 | 克制表里 21 组“克制”关系有 19 组在同指挥点对战中成立；不成立的是憎恶、缝合巨怪打 12 名弩手（弩手射程 7 格，人多，近战重装走不到身前就倒了） | 克制方向没问题，但**克制太绝对**：45 组单一角色对战里 44 组胜率在 10% 以下或 90% 以上。可以考虑把最极端的倍率收一点（飞骑打重装 1.8 / 重装打飞骑 0.3、对空打飞骑 2.5），让“带了克制”变成优势而不是必胜 |
| 性价比 | 加进标准混编的边际价值：弩手约值 1.8 指挥点（定价 1）、奥术法师约值 4.4（定价 2）偏强；重甲骑士 4.8（定价 4）、游侠 2.5（定价 2）合适；狮鹫骑士约 0.5（定价 1）偏弱 | 先不改。奥术法师偏强是因为模拟里魔网完整、没人切线，它的弱点（法力、魔网）没体现出来；狮鹫的价值在切断魔网，这个测法看不到。等远征平衡模拟一起看，再决定是否把弩手的伤害或奥术法师的法力调低 |
| 亡灵定价 | 招募亡灵后的参考指挥点：食尸鬼约 2、憎恶约 4、毒雾骨塔约 3.5、缝合巨怪约 6.5；怨灵和狮鹫骑士一样测不准 | 亡灵变成可招募角色时按这个定价 |
| 升星 | ★2、★3 每升一星大约顶 1.8、1.7 名低一星；按新加的 ★4、★5 倍率是 1.5、1.4，★5 约等于 5 名 ★1。远征里 3 合 1 会亏一点战力，换来省格子和指挥点 | ★4、★5 的提升比前两星小，是有意的：后两星碎片最贵，同时还有等级和符文槽在涨。不动的毒雾骨塔升星收益特别高（射程远、站桩），如果亡灵炮台可招募要单独压它的星级倍率 |
| 站边偏差 | 双方完全相同时，站在左边（我方）的胜率在 8%~100% 之间摇摆，但剩余耐久几乎打平：内核先结算我方再结算敌方，势均力敌时决定谁先倒 | 不影响正常对局（双方阵容不同）。如果以后做异步对战，要让伤害在同一帧同时结算 |
| 战场环境 | 四种已实现的环境对四种代表阵容的优势分改变都在 15 个百分点以内（最大是灰沙荒漠下“骑士团为主”+13：亡灵地面部队被减速，狮鹫不受影响） | 不用削弱 |
| 地块 | 高地、灌木对弩手、奥术法师、毒雾骨塔明显有利（优势分 +5~+17）；沼泽对所有地面角色都是明显的减益；**骨堆对亡灵重装太强**（憎恶 +20、缝合巨怪 +27） | 骨堆每秒回复 2% → 1%，或者改成“每秒最多回复 10 点”，第 3 章做骸骨荒原时一起调 |

调整数值时：先改 JSON，跑 `-- --balance` 看平衡表，再跑一遍普通测试看远征平衡模拟。

## 10. 炼金工坊：缴获与解析

原型图见 [prototype/Lab.png](prototype/Lab.png)。

- 远征中缴获的遗骸全部带回灯塔城（失败带回一半）。
- 用遗骸在炼金工坊发起**解析研究**。

**研究时间：现实时间为主，实战缩短为辅**

| 研究对象 | 基础时间 |
|---|---|
| 普通敌人 | 12 小时 |
| 精英敌人 | 18 小时 |
| Boss 武器 | 48 小时 |

- 关闭游戏也会计时；完成后成果一直保留，不会过期。
- **实战缩短随剧情解锁**：

| 阶段 | 解锁时机 | 效果 |
|---|---|---|
| ① | 首次击败骸骨要塞：林大师带回第一批亡灵样本，炼金工坊开放 | 只有现实时间倒计时 |
| ② | 首次击败噬魔巨龙：炼金工坊接入远征军的战报 | 赢一场战斗 −1 小时，击败 Boss −3 小时，完成一局远征 −2 小时 |
| ③ | 首次击败巫妖王：诺娃协助解析，升级为“星辉秘仪室” | 缩短效果翻倍，研究槽 +1 |

- 额外消耗同类遗骸可以加速（每个 −2 小时）。

**研究成果分阶段发放**

| 进度 | 成果 |
|---|---|
| 25% | 揭示该敌人的隐藏特性，以后战前推演对它不再有误差 |
| 60% | 获得它的武器符文图纸，符文加入奖池 |
| 100% | 解析成功，该敌方单位加入奖池和图鉴 |

- 研究不会失败。初始 2 个研究槽，最多 4 个。研究树按阵营分支（亡灵秘术、精灵秘术）。

## 11. 常驻休闲玩法：星辉高塔

原型图见 [prototype/Tower.png](prototype/Tower.png)。

### 11.1 设定

灯塔城外有一座通往云端的远古高塔，每一层都嵌着一颗熄灭的星辉水晶，塔里盘踞着亡灵，没人知道塔顶有什么。远征军沿着这座**星辉高塔**一层层往上打，每打赢一层就点亮一颗水晶。

- 一层一场战斗，1~2 分钟。**没有体力、没有每日次数、进度永久保留。**

### 11.2 深度区段

| 层 | 区段 | 特点 |
|---|---|---|
| 1~20 | 塔基 | 教学性质，敌人以轻装、重装为主 |
| 21~40 | 古战场 | 怨灵增多，考验弩手布置 |
| 41~60 | 迷雾回廊 | 法力紊乱规则（魔网连线距离缩短等） |
| 61~80 | 虚空裂隙 | 漩涡、传送单位 |
| 81~100 | 亡灵王座 | 高难度规则层和 Boss 集中 |
| 101 层以上 | 无尽星穹（无尽） | 固定种子程序生成，可上排行榜 |

每 10 层：1~8 层普通层（其中 2~3 层带规则），第 9 层精英层，第 10 层 Boss 层兼存档点。

### 11.3 每层的玩法

- **敌方阵容完全公开**，像一道布阵谜题；**失败可无限重试**。
- 每层 2 点情报点，进入新的一层时补满。
- **规则层**（重点考验魔网）：只能放 1 个法力水晶；魔网连线连接距离降为 2 格；看不到敌方后两排；本层没有源晶塔；中央有法力漩涡；敌方怨灵翻倍。

### 11.4 塔内编队与塔层祝福

- 使用主线和炼金工坊**已解锁**的角色、符文、指挥官技能，**强度统一**，不受养成数值影响。
- 指挥点上限随深度提升（塔基 14 点，每个区段 +4）。
- 每过一个 Boss 层，从 3 个**塔层祝福**中选 1 个长期装上，例如：魔网连线连接距离 +1、法力水晶耐久 +50%、陨星术冷却 −30%、开局法术点数 +2、狮鹫离网时间 +5 秒。最多 6 个，存档点可重新调整。

### 11.5 星级与奖励

- 每层 3 颗星：通关；损失不超过 2 名；本层特殊条件。
- 首通奖励：金币、遗骸、少量局外货币；每 10 层里程碑奖励称号、外观、灯塔城装饰。
- **不发放直接提升战力的物品**。
- 排行榜：最高层数、总星数，由服务器记录，可只看好友。长期榜，不分赛季。

## 12. 联网与在线玩法

玩家必须连接服务器、登录（小游戏用微信账号，决策 66）后才能玩（决策 49）。养成数据存在服务器上，换设备登录即可继续。下面的在线玩法是可选的，不玩也没有损失。

| 玩法 | 规则 |
|---|---|
| 玩家阵容节点 | 远征中遇到其他玩家同一幕的真实阵容（异步，主要的在线内容） |
| 排行榜 | 星辉高塔最高层、总星数；每日固定种子的“每日地图”分数（可选，不玩无损失） |
| 微信好友排行（v4.0） | 高塔层数、通关章节，只在好友之间比；可以分享战报，但**分享不换任何奖励**（微信禁止诱导分享） |
| 竞技场 | 上传防守阵容，挑战排名更高的玩家，赢了交换名次（异步，能看到对方阵容）。**输赢都给经验和金币**，打输也不白打；名次长期保留，**不分赛季**，首次达到某个名次档位发一次性奖励（外观、金币），不发直接提升战力的物品 |
| 实时对战（后期） | 双方 60 秒盲布阵，三局两胜；服务器用确定性内核计算 |
| 通关录像（草案） | 低战力通关自动上传录像，卡关的玩家下载参考、照抄布阵；方案见 [replay-server.md](replay-server.md) |

防作弊：所有战斗在客户端播放，结束后服务器用同一个确定性内核重跑，以服务器结果发奖励；货币、碎片、等级、掉落都由服务器计算（见 [server-design.md](server-design.md)）。

## 13. 展现方式与美术

- **启动和存档**（决策 69 取代决策 42 的存档位部分）：微信登录后直接进主界面，一个账号一个存档，不再有三个存档位。第一次打开不先起名，30 秒内进第一场战斗，打完第一关再给持线人起名。
- **2D 界面 + 3D 战斗**：望星城、地图、商店、天工坊、摘星楼用 2D 界面；布阵和战斗在 3D 场景中。
- **竖屏、单手**：界面以竖屏手机为基准设计（取代决策 31 的 4K 横屏），常用按钮放在屏幕下半部分。战场竖向摆放，我方在下、敌方在上（决策 52）。
- **镜头**：布阵时接近正俯视；点“开战”后镜头压低，从我方身后斜看。战斗中只有默认和俯视两个预设视角。
- **风格：星宿国潮**（决策 68，详见 [art-direction.md](art-direction.md)，待改写）：Q 版大头的角色继续用 Blender 脚本生成，服装、发型、配饰换成东方样式（甲胄、劲装、道袍、狐耳和花冠）。配色是宣纸米白、墨、朱砂、石青和金；星线和星络是画面里最亮的金色光。墨蚀者用墨色剪影和发光的眼睛，不用骷髅、尸体、腐肉和血腥；去掉十字等宗教符号。夜景（登录、主界面）用墨蓝夜空和金色星宿连线，和界面方向 A“星图”一致；局内面板用宣纸色。
- **渲染**：URP；小游戏上关掉实时阴影，泛光只留给星络、星石和技能，角色用烘焙阴影贴图和描边。
- **音乐**：民乐配器（古筝、笛、编钟、鼓），所有曲子仍围绕同一段“星线主题”变奏（[music.md](music.md)，待改写）；第一版由脚本程序化生成，放 CDN 按需下载。
- **重点投入**：技能光效、星络连线点亮和断开、星石点亮、胜利结算。

## 14. 技术架构

### 14.1 结构

```
Unity 客户端（Starline/Packages/com.starline.game）
├── Runtime/Client     表现层：GameApp 入口、各界面（UI Toolkit）、布阵与战斗控制、3D 舞台
├── Runtime/Resources  配置表（JSON）、界面布局（UXML）与主题（USS）
└── Runtime/Battle     战斗内核（纯 C#，不依赖 Unity）
    ├── Data           配置读取、角色数据、克制表
    ├── Board          棋盘坐标、布阵规则、魔网
    ├── Sim            战斗模拟、指挥官技能
    ├── Analysis       战前推演
    ├── Expedition     远征：地图、远征军与合成、奖励、自动布阵
    ├── Replay         录像（录制、JSON、回放、校验）、上阵战力、关卡固定种子
    └── Math           定点数、确定性随机数
```

详细说明见 [client-architecture.md](client-architecture.md)。

### 14.2 关键决策

| 决策 | 理由 |
|---|---|
| 内核与 Unity 分离 | 可以写自动化测试；推演能在后台批量模拟 |
| 定点数 + 固定种子 | 结果在任何电脑上一致：推演、回放、在线对战都依赖它 |
| 数据驱动 | 角色、敌人、技能、地图、奖池、剧情文本都在 JSON 配置表里，内核和测试读同一份 |
| 存档在服务器上，必须联网登录 | 防作弊、录像和排行榜都依赖服务器为准的数据；换设备登录即可继续 |
| 服务端 C# 云函数托管在 UOS，数据库先用 CRUD Save、后换 MySQL（见 [server-design.md](server-design.md)、[server-database.md](server-database.md)） | 和内核同语言，服务端能直接引用内核重跑战斗；账号用微信登录（v4.0，原为 Steam），养成数据按存档存，设置和录像按账号存；战斗在服务端重跑结算 |

### 14.3 仓库结构

```
XFramework/（仓库）
├── Starline/                         Unity 工程
│   └── Packages/com.starline.game/   游戏代码
├── src/Starline.Battle/              用 .NET 编译战斗内核
├── tests/Starline.Battle.Tests/      内核测试与平衡性模拟
├── server/db/                        服务端 MySQL 建表语句
└── docs/                             设计文档与原型图
```
