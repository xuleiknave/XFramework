# 美术方向与角色模型

> v6.0（决策 77）：题材从“西游后传”改回《西游记》原著原班人马，阵营改成人、仙、魔、兽四族。国潮配色、竖屏界面、圆润卡通和制作流程都保留，换的是阵营色（第 2 节）和角色造型（第 4 节）。仓库里现有的 FBX 和预览图还是 v3.0 西幻造型，模型 id 不变，按新造型重做后替换同名文件即可。v5.0 和更早的文字见 git 历史。

题材是《西游记》原著：唐僧师徒西行，战场上的灵力节点叫灵石，连成灵脉（见 [game-design.md](game-design.md) 第 2 节、[story.md](story.md)）。这里记录美术规则和模型的制作流程。旧界面稿在设计画布上：[星线 美术与界面设计](https://claude.ai/artifact/43WiNNPkBcqsKzZCwcpq29)（v3.0 配色，布局仍可参考）。

## 1. 风格：桌上棋子 + 金色灵脉

圆润卡通的东方角色，每个角色是一枚摆在宣纸棋盘上的棋子；灵脉是画面里最亮的金线。参考方向是“国潮插画 + 手游 Q 版”，不是写实古装，也不是水墨写意。

| 原则 | 说明 |
|---|---|
| 竖屏、小屏先看清 | 首发是微信小游戏，手机竖屏、一名角色只有三四十像素高。每个兵种靠一个夸张的特征认出来：悟空的金箍棒、八戒的钉耙、沙僧的担子、唐僧的锡杖 |
| 颜色就是阵营 | 四族各有一种颜色（见第 2 节），衣服大块用阵营色，敌我在棋盘上一眼分开 |
| 灵脉是光 | 灵石、土地庙和灵脉连线是金色的光。每名角色脚下一圈光环：接入灵脉时常亮，断开时变暗、闪朱砂红 |
| 纹样点到为止 | 云纹、回纹、八卦纹只用在饰边、底座和面板角上，不铺满；不画龙袍、不用宫廷黄，避免像“古装剧” |
| 审核红线 | 不出现骷髅、尸体、腐肉、血液、吃人和十字架、教堂等宗教符号；佛、道尊神不做成敌人，寺庙、道观不做成可破坏的建筑。妖怪画成 Q 版的兽形和人形，靠獠牙、角和发光的眼睛显得凶，不画伤口和血。原著里的白骨精这类以骷髅为原型的妖怪不做；三清、如来、观音、玉帝等尊神可以做成卡，但不做成敌人 |
| 原著人物自己设计 | 哪吒、牛魔王、小白龙、孙悟空等原著人物的造型自己从原著文字出发设计，不参考 86 版电视剧、《大闹天宫》动画、《黑神话：悟空》《大圣归来》等任何改编作品；给 AI 生成工具的描述里也不写这些作品名 |

## 3. 界面：墨蓝夜空 + 宣纸面板

- **竖屏**：按 1080 × 1920 设计（微信小游戏和手机 App 共用），按屏幕宽度缩放，顶部和底部留出刘海与手势条的安全区。横屏的 3840 × 2160 设计稿作废（见 [client-architecture.md](client-architecture.md) 第 3 节，待改）。
- **单手操作**：主要按钮放在屏幕下半部分，大拇指够得着；战斗里只有“加速”“跳过”和 1~2 个指挥官技能按钮。
- **面板**：宣纸底 + 一像素墨线，四角各一个小云纹角花；标题栏用墨底金字。不做浮雕、卷轴展开动画和满屏花纹。
- **标题**：界面名、角色名用墨色或金色的宋体；主按钮朱砂底宣纸色字，次按钮宣纸底墨线墨字。
- **灵脉金**用作分隔线、选中态、灵力点数和地图上走过的路；可前往的路用虚线金。
- **主菜单**：沿用界面方向 A 的布局（夜空里的连线就是菜单），颜色换成墨蓝夜空 + 金色灵脉；前景是土地庙和师徒几人站在光环上待机，地平线上是五行山剪影、花果山的水帘和火焰山的红光。
- **字体**：正文和数字用 Noto Sans SC（已随包）。标题用思源宋体（Noto Serif SC，SIL OFL），还没放进工程；小游戏包体有限（主包 4 MB），只放 Bold 一个字重，并按游戏里实际用到的字裁剪。西文 Cinzel 标志不再使用。

### 角色总则：圆润卡通

开发者看过第一版低多边形样品后要求“不要那么多边形感，卡通一点，但要看得到细节”，所以角色都用**圆润卡通**：

| 项目 | 规定 |
|---|---|
| 造型 | 头身比约 1:3，大头、大眼睛（带高光）、小鼻子、粗眉毛；手是圆球，靴子和盾牌是圆角方块 |
| 细节 | 用小零件补：铆钉、金色滚边、腰带、流苏、玉佩、云纹护肩、发簪、葫芦、桃子、鳞片等 |
| 着色 | 平滑着色，折角大于 50° 的边保持硬边；仍然是 Hull 和 Glow 两个材质槽 |
| 贴图 | 每名角色单独展开 UV，把“色块颜色 × 环境光遮蔽（AO）”烘焙进专属贴图 `<模型 id>_tex.png`（768 × 791）；客户端发现这张贴图就用它 |
| 描边 | 反向外壳：沿法线外扩 0.012、翻转朝向的墨色网格（#1E2230），只在轮廓处露出一圈线，不需要专门的着色器 |
| 面数 | 小游戏版每名角色含描边不超过 8000 个三角面（★5 最多），现有脚本的 1 万~2.6 万要降 `SEG`；App 版可以用高一档 |

第一幕的 15 个单位暂时保持低多边形（小妖、熊妖等普通妖兵的墨色是 v5.0 留下的，重做时改成第 2 节魔族色）；其中土地庙、灵石、妖坛三座建筑要和卡通角色站在一起（主菜单），优先改成圆润卡通（建筑描边加粗到 1.8 倍），底座边上的发光环仍表示灵脉状态。

### 骨骼动画和底座（决策 46）

卡通角色带骨骼和动画导出，战斗里不放底座。

- **骨骼**：建模时登记骨骼，所有角色用同一套名字：`root`（脚底中心，整体位移和倒下）、`hips`、`spine`、`head`、`leg.R/L`、`arm_upper.R/L`、`arm_lower.R/L`、`cape`（披风）；飞骑另有 `mount`（坐骑身体）、`mount_head`、`mount_tail`、`wing.R/L`，骑手的 `hips` 挂在 `mount` 上。傀儡和树灵也用同名骨骼，只是比例不同；猴尾、龙尾挂在 `cape` 上
- **绑定**：卡通角色是一块块零件拼的，每块零件整块绑到离它最近的骨骼（刚性绑定，没有权重过渡）；武器自动绑在拿着它的那只手上，披风绑 `cape`，翅膀绑 `wing`。描边外壳跟着原来的零件动
- **动画**（24 帧每秒，FBX 里的动画名是 `<模型 id>_rig|<动画>`）：

| 动画 | 长度 | 内容 |
|---|---|---|
| idle | 2 秒循环 | 轻微起伏、歪头、披风飘；飞骑扇翅膀 |
| walk | 0.67 秒循环 | 迈腿摆臂、一颠一颠、前倾；长袍角色扭胯；飞骑快速扇翅 |
| attack | 0.58 秒 | 按风格：劈砍、突刺、拳击、射击（拉弦后坐）、投掷、施法（双手前举）；飞骑的坐骑先扬翅再俯冲 |
| hit | 0.33 秒 | 上身和头后仰 |
| death | 1 秒，停在最后一帧 | 向后倒下后化成光点（妖魔化成墨烟）；飞骑翻落 |

战斗默认 2 倍速（决策 69），动画要在 2 倍速下仍然看得清，attack 的出手帧不要晚于一半。每名角色的攻击风格在 `build_models.py` 的 `ATTACK_STYLE` 里。客户端 `UnitAnimator` 用 Playables 播放：移动时 walk、停下 idle，开火时 attack，受击 hit（不打断攻击），被击败先播 death 再移除。

- **底座**：单独导出 `base_s1` … `base_s5`（1 格）和 `base_large_s1` … `base_large_s5`（2×2），顶面高 0.08。展示、升星、图鉴界面用 `ModelLibrary.InstantiateShowcase` 把角色放在对应星级的底座上；战斗里角色直接站在棋盘上，脚下一圈地面光环显示灵脉状态。角色模型的最低点在 0（脚底）
- 第一幕的 15 个低多边形单位还是静态模型、自带底座，以后按同样方法重做

| 项目 | 规定 |
|---|---|
| 尺寸 | 1 格 = 2 个 Unity 单位。1 格角色的底座半径约 0.75，2×2 单位约 1.6 |
| 朝向 | 正面朝 Unity 的 +Z（Blender 的 -Y），轴心在底面中心；鹤骑和阴风怪的悬空高度由客户端另加 |

### 制作流程：脚本生成

模型由 `tools/models/build_models.py` 用 Blender 生成。每个单位是一个函数，用底座、小人、多面晶石、圆锥、低面数球体拼出来。

```
blender --background --python tools/models/build_models.py -- --preview docs/art/models
```

也可以用 `pip install bpy` 装好的 Python 模块直接运行 `python3 tools/models/build_models.py --preview docs/art/models`。

- 输出：`Starline/Packages/com.starline.game/Runtime/Resources/StarlineModels/<单位 id>.fbx` 和 `Palette.png`；加上 `--preview` 时会把预览图渲染到 `docs/art/models/`。
- 客户端按单位 id 加载模型（`ModelLibrary`），某个单位没有模型时自动退回几何体占位。
- 新增单位：在脚本里加一个函数并登记到 `UNITS`，重新运行即可。也可以在 Blender 里打开导出的 FBX 手工修改，但下次运行脚本会覆盖同名文件。
- 改成西游后传要改脚本里的 `PALETTE`、各角色函数的零件（猴尾、猴耳、葫芦、风火轮、龙角、鳞片、龟壳、长幡等）和描边颜色；`docs/art/models/` 下的预览图到时一起重新渲染。

### 制作流程：外部模型导入（AI 生成或美术交付）

开发者的目标是“云顶之弈的清晰度，但更卡通”。脚本拼几何体到不了这个水平（没有手绘贴图），所以正式角色改为用 AI 3D 生成（首选 Tripo）或美术交付带贴图的模型，再用脚本统一成工程规格：

```
python3 tools/models/import_model.py 模型.glb 单位id [--turn 角度] [--cells 1|2] [--no-base] [--faces 8000] [--preview 预览.png]
```

- 支持 .glb / .gltf / .fbx / .obj，需要一张接在 Base Color 上的颜色贴图
- 合并网格；`--turn` 把正面转到 Blender -Y（Unity +Z）；轴心放到底面中心；按高度缩放（1 格 1.6、2×2 3.2，`--height` 可改），并保证不超出底座
- 超过 `--faces` 时减面（小游戏版用 8000）；加棋子底座和灵脉发光环（悬空单位加 `--no-base`），底座颜色写进贴图顶部新加的色带，所以仍是一张贴图
- 输出 `StarlineModels/<单位 id>.fbx` 和 `<单位 id>_tex.png`；客户端 `ModelLibrary` 发现 `_tex` 贴图时用它，否则用共享的 `Palette.png`
- 给 AI 的描述用“Q 版国潮、圆润卡通、东方神话”，并写明不要骷髅和血，不写任何改编作品名；生成后按第 1 节的审核红线检查
- 商用要求：Tripo 免费版生成的模型不能商用，要用付费版或 API
