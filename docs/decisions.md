# 决策记录

Starline 从立项到现在做过的关键决定，按时间顺序，每条写明“定了什么”和“为什么”。设计细节以 [game-design.md](game-design.md) 为准，完整讨论见 [conversation-log.md](conversation-log.md)。

## 立项

| # | 决定 | 理由 |
|---|---|---|
| 1 | 不做 Unity 仿真推演平台，改做游戏 | 市面上已有成熟的商业和开源仿真平台，个人再做一套意义不大；把“战场推演”的经验用在游戏上，可玩性和商业空间更大 |
| 2 | 题材：科幻、宇宙舰船 | 避开现代军事题材可能带来的审查和泄密顾虑；科幻可以做到宇宙级别，想象空间大 |
| 3 | 单机为主，不打卡 | 开发者偏好单机；玩家不用定时定点做任务，每天约 30 分钟能玩完一轮 |
| 4 | 舰船数量控制在约 20 种（首发） | “上百种”对个人开发者的美术和平衡成本太高；靠合成升星和组件组合提供深度 |
| 5 | 平台：先做 Steam，买断制；暂不做微信小程序 | 曾考虑用团结引擎发微信小游戏（个人主体只能靠激励视频广告变现），但开发者手上的团结引擎是 1.5 版，决定先不做小程序、改用最新版 Unity 做 Steam 版；广告变现只适用于小程序方案，Steam 版用买断制 |
| 6 | 引擎：Unity 最新版（本地 6000.6.6），URP 渲染 | 开发者熟悉 Unity；URP 提供 HDR 泛光等后处理，比内置管线效果好 |

## 玩法

| # | 决定 | 理由 |
|---|---|---|
| 7 | 战斗自动进行，战前排兵布阵（类似自走棋） | 战斗要快；策略集中在布阵，单人开发不需要做复杂的实时操作和 AI 微操 |
| 8 | 保留指挥官技能（轨道打击、紧急护盾等） | 给自动战斗留一点参与感和翻盘手段 |
| 9 | 关卡中能看到敌方阵容；实时对战看不到；加天梯挑战他人防守阵容 | 看得到才能针对性布阵；实时对战靠盲布阵增加博弈 |
| 10 | 装备：固有属性为主，2~3 个扩展槽为辅，组件与舰船双向限制装配 | 组件只能补充，不能改变舰船的定位和玩法，否则平衡失控、舰船失去辨识度 |
| 11 | 从“长期养成 + 关卡战役”改为 Roguelite 远征 | 开发者担心慢节奏收集类游戏不受欢迎；Roguelite 每局 25~30 分钟、每局不同，节奏快、重玩性高，养成改为轻量的解锁 |
| 12 | 展现方式：2D 界面 + 3D 固定镜头战斗 | 远征结构以界面为主，自由视角 3D 不划算；战斗保留 3D 但镜头固定，美术成本可控 |
| 13 | 创新玩法：补给网络 + 战前推演 | 来自开发者的仿真推演背景；补给线让站位有意义，“推演一百场”是同类游戏没有的卖点 |
| 14 | 缴获与逆向独立成“实验室”模块，现实时间为主、实战缩短为辅，随剧情解锁 | 给玩家一个局外的长期目标；现实时间让每天回来有东西可领，实战缩短奖励爱玩的玩家 |
| 15 | 棋盘从 4×6 改为每方 8×6（前排 8、纵深 6），大型舰船占 2×2 | 加入补给网络后格子太少，摆不出有意义的补给线 |
| 16 | 横向布局：我方在左、敌方在右；布阵和战斗都是侧面横看；操作面板放左侧 | 竖向布局的战斗视角不好看；横向更像舰队对阵 |
| 17 | 补给节点放在格子交叉点上，补给线沿格线走（连接 ≤ 3 格，覆盖 2 格） | 节点不占格子，不和舰船抢位置，规则也更清楚 |
| 18 | 常驻休闲玩法：爬塔，后定名“深空信标链” | 主线之外需要碎片时间玩的内容；一层一场、无体力、可无限重试，长期目标是走得更远 |

## 名称与世界观

| # | 决定 | 理由 |
|---|---|---|
| 19 | 项目名 Starline（星线） | 既指“星际航线”，也呼应补给线这个核心玩法 |
| 20 | 世界观改为“重建星线”，全部战斗在太空，兵器统一为舰船 | 原来“从地球打到宇宙”会让地面武器和太空武器同场作战，显得不伦不类；“重建补给航线”和补给网络玩法在主题上一致 |
| 34 | 背景从太空科幻换成奇幻“魔网”：法力水晶织成的星线、人类远征军对亡灵，玩法和数值不变 | 开发者不想再做太空战役题材；在仙侠、深海、浮空群岛、奇幻四个方案中选了奇幻，海外玩家最容易理解。项目名“星线”保留（水晶由流星碎片化成，连起来像星河），代码里的单位 id 不改，术语对照见 game-design.md 附录 |

## 开发

| # | 决定 | 理由 |
|---|---|---|
| 21 | 战斗内核是纯 C#、定点数、固定种子，不依赖 Unity | 结果在任何电脑上一致（推演、回放、在线对战都依赖它）；能用 .NET 写自动化测试和批量模拟 |
| 22 | Unity 代码放在嵌入式包 `Starline/Packages/com.starline.game` | 代码和工程资源分离，同一份内核源码被 Unity 和 .NET 测试项目共同编译 |
| 23 | 原型阶段界面用 IMGUI，模型用基本几何体 | 不依赖场景和美术资源，先把玩法跑通 |
| 24 | P2 的数值用“自动玩家”批量模拟来校准 | 个人开发者没有测试团队；自动玩家（不用技能、随机选路线）通关率约 40%，真人应明显更高 |
| 25 | 指挥点上限按“过一个战斗节点 +2”增长，输赢都算 | 模拟发现只按胜场增长会滚雪球：输一场就越来越难 |
| 26 | 战斗中被击毁的舰船战后全部修复 | 失败的代价由舰队耐久承担，避免一场失败让整局崩盘 |
| 27 | 正式开发：保留战斗内核，重建 Unity 客户端 | 内核有完整测试和平衡模拟，推倒重来要重新校准；原型客户端（IMGUI、单个大类）不适合继续扩展 |
| 28 | 界面用 UI Toolkit | Unity 6 主推；类似网页的 UXML/USS，适合菜单、星图、面板多的策略游戏，样式集中好改，能用 UI Builder 可视化编辑 |
| 29 | 数值用 JSON 配置表，放在 Resources/StarlineData | 内核和 .NET 测试直接读同一份数据；数值按十进制精确转换成定点数，不破坏确定性；以后可以从 Excel 导出 |
| 30 | 界面字体用 Noto Sans SC Regular，随包提供 | SIL OFL 协议，可免费用于商业游戏并随游戏分发；系统自带的微软雅黑、苹方等不能随游戏分发。只放 Regular 一个字重（约 10 MB），粗体由引擎合成，以后需要再加 |
| 31 | 界面按 3840 × 2160（4K）设计，按屏幕高度缩放；清晰度（渲染分辨率）以后在设置界面里选 | 开发者要求按 4K 设计：像素值和美术出图都以 4K 为准，低分辨率屏幕等比缩小，画面不会因放大而发虚 |
| 32 | 美术方向：低多边形“桌面战棋”部队，形状认兵种、颜色认阵营；每支部队底座有发光环，表示是否接入魔网 | 战斗镜头里部队很小，必须靠剪影和颜色一眼认出；魔网是核心玩法，用光直接画在画面上。界面敌我色仍用蓝 / 橙，亮度差大、色弱也能分清 |
| 33 | 部队模型用 Blender 脚本生成（`tools/models/build_models.py`），共用一张色块贴图 | 个人开发者美术成本最低；风格统一，改了重跑即可；换题材时只需改脚本里的单位函数 |
| 35 | 界面风格“星夜金边”：深蓝夜空底、金色细边框和金色标题、金色主按钮，选中和进度用魔网青绿 | 开发者在三种风格里选定。只描轮廓不做浮雕和纹理，4K 下干净、缩小到 1080p 也不糊；光留给棋盘上的魔网 |
| 36 | 首发约 45 种：我方 20 名角色、敌方 25 种单位 | 开发者先选了这个规模，再扩充靠更新 |
| 37 | 单位按“角色”计算：棋盘上每个单位是一个人（或一只怪物），不再是一支小队；每名角色配 1~2 个专属技能 | 开发者要求。单个角色更容易有辨识度和个性，技能也更好挂在角色身上；合成升星仍是 3 名同名角色。模型改为单个人物，放大到在战斗镜头里看得清 |
| 38 | 我方角色有名字（显示为“名字 · 职业”），按出身和职业组成 11 个羁绊（5 + 6），同名角色只算一次 | 开发者要求给角色起名、加阵营羁绊。有名字的角色更有个性、方便写剧情和喊话；自走棋式羁绊让收集新角色有目标，也让布阵多一层取舍。五个出身各 4 人，2 / 4 人激活，单局 8~10 名角色的奖池里也凑得出来 |
| 39 | 角色不分敌我：五个阵营各 9 名，共 45 名，敌对阵营打赢、唤醒或结盟后可招募；用一条主线故事串起来（`docs/story.md`） | 开发者要求。敌人也能收集，收集目标翻倍，故事也有了“唤醒亡灵、与精灵结盟”的主线 |
| 40 | 成长改为刷关升级、集碎片升星（草案）；不做体力、每日次数和付费抽卡 | 开发者要求。保持买断制：刷图只花时间，用扫荡和自选碎片控制重复劳动 |
| 41 | 主线改为章节关卡；原来的 Roguelite 远征保留为挑战模式，带自己培养的角色出发，产出碎片 | 开发者选定。现有远征代码和平衡模拟能继续用，玩家多一种玩法 |
| 42 | 主菜单就是首页：启动直接进主菜单并读取最近玩过的存档；三个本地存档位从主菜单的“存档”进入，每个存档是一名有名字的指挥官；不做账号登录 | 开发者选定主菜单作首页，少一步点击。单机买断制没有服务器账号，存档位方便家人共用一台电脑或重开一局；Steam 云存档以后同步存档文件夹即可 |
| 43 | 设置界面先做语言和画质；画质用四档预设加单项微调，改动立即生效并自动保存，显示模式和分辨率改完要确认；设置所有存档共用 | 开发者要求先做这两项。预设让大多数玩家点一下就好，单项留给懂行的玩家；立即生效省掉“应用”按钮，确认倒计时防止换分辨率后黑屏。首发语言是中文和英文（设计文档 Q5），英文翻译完成前先显示“翻译制作中” |
